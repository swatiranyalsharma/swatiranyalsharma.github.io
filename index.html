02 / SYSTEM DESIGN

Scalability and architecture

01

Choosing data stores

I match the store to the workload: MySQL or MongoDB for application data, ClickHouse for analytics over large volumes.

02

Caching

I use Redis for data that is read often and changes rarely, and decide expiry and invalidation before adding a cache.

03

Service boundaries

Each microservice owns one responsibility and exposes a clear API contract, so one service can change without breaking others.

04

Traffic and bottlenecks

Before scaling anything, I measure request rate, latency and the slowest queries, then fix the real bottleneck.

05

Consistency vs availability

For each workflow I decide whether stale data is acceptable or strict consistency is needed, and design around that.

06

Monitoring

I build dashboards and alerts so problems show up before users report them.
